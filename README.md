### MySQL

前四篇成体系，建议按 **原理 → 建表 → 调优 → 拆分** 的顺序读，后三篇的每条规范都标了 **⤵ 依据**，指回第一篇；第五篇换一个轴，讲**数据怎么流出去**。

| 笔记 | 层次 | 内容 |
|---|---|---|
| [B+ 树原理](mysql/B+树原理.md) | **为什么** | 为什么不用哈希/红黑树/B 树、用具体数据把树完整拆开（上下层 key 如何对应、叶子页里一行怎么存）、3 层为什么能装 2190 万行、页内 Page Directory 二分、页分裂与自增主键、聚簇索引 vs 二级索引、**联合索引专章**（元组排序、六条 SQL 的树上走位、IN 不截断、ORDER BY 免 filesort、列序三步法、几列才合适与定位列 vs 携带列）、深分页为什么慢 |
| [数据表设计](mysql/数据表设计.md) | **建表时** | 六项设计原则（数据量/数据关系/数据规范 + 命名/字段类型/索引）、四条实战经验（字段≤20、全 NOT NULL、索引≤6、冗余换查询）、烂表改造实例、规范与 B+ 树的依据对照表、建表 Checklist |
| [索引优化](mysql/索引优化.md) | **上线后** | 冗余索引识别、最左前缀与索引字段顺序、`key_len` 反推用了几列、索引下推 ICP、索引覆盖、EXPLAIN 字段速查、索引规则与 B+ 树的依据对照表 |
| [分区表与分库分表](mysql/分区表与分库分表.md) | **撑不住时** | 分区表管「整理」、分库分表管「分散」；RANGE 分区实操（`TO_DAYS`、`MAXVALUE` 为什么堵死 `ADD PARTITION`、`REORGANIZE` 怎么劈开它）、**分区键为什么必须进每一个唯一索引**、`DROP PARTITION` 才是分区表的真正价值、分区裁剪与最左前缀同理；user 表实战：先统计访问方式再定分片键、**先垂直后水平的三个理由**（垂直拆完可能就够了）、两级哈希、分片数为什么要取 2 的幂、全局 ID 的鸡生蛋问题、**不带分片键的登录查询怎么办**（映射表/基因法/ES）、分片后失去了什么（跨库 JOIN/事务/深分页/唯一约束） |
| [binlog](mysql/binlog.md) | **数据流** | binlog 把「数据库状态」变成「可订阅的变更流」；先分清 **redo log（怎么改的，只有 InnoDB 看得懂）vs binlog（改成了什么，谁都能消费）** 与两阶段提交；三种格式（`SYSDATE()` 不安全而 `NOW()` 安全、`DELETE ... LIMIT 1` 主从分叉、为什么 CDC 只认 ROW、`binlog_row_image` 别设 MINIMAL、**DDL 永远是 STATEMENT**）；`sync_binlog` 与组提交；**八个用途分两族**——MySQL 自用（复制 / PITR / **误删闪回**）与外部订阅（异构同步 / **缓存一致性**：binlog 是"事务已提交"的凭据 / **替掉分库分表迁移的双写** / 解耦 / 审计）；Canal 伪装成从库的原理 |

## 约定

- 按主题分目录：`spring/`、`jvm/`、`concurrency/` ……
- 一篇笔记一个 md，文件名用中文或英文都行，保持可读优先
- 涉及源码的结论尽量**实际跑一遍验证**，并把真实日志贴进笔记
- 代码片段标注出处（类名 + 方法名），方便回头断点跟踪
